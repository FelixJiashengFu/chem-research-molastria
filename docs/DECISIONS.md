## 2026-11-08 桌面版去掉 panic = "abort"

Mac 版 0.1.19 在后台运行约 25 分钟后闪退（SIGABRT，tokio-rt-worker 线程）。按崩溃报告里的偏移反汇编发布包，调用链是：异步回应应用内置协议请求时调用 WKURLSchemeTask 的 `didFinish`，WebKit 已经停掉了这个请求（页面换了、iframe 或视频取消了请求），于是抛出 Objective-C 异常。wry 用 `objc2::exception::catch` 包住了这个调用，本来只会丢掉这次回应；但 `Cargo.toml` 的发布配置写了 `panic = "abort"`，objc2 的文档写明这种设置下接不住异常，Rust 只能报“panic in a function that cannot unwind”并结束整个进程。
**原因：** 应用体积只多一点（unwind 表），换来 wry 的防护真正生效；顺带，命令或后台任务里偶然的 Rust panic 也只结束那一个任务，不再带走整个应用。Windows 不会遇到这个 Objective-C 异常，但两边共用这份配置。以后不要再加回 `panic = "abort"`。

站长的 L4 虚拟机不开公网服务，由 `tools/cloud/run.mjs` 经 gcloud 开机、计算、取回、关机，结果用 AI 实验室原有的 CSV 导入。MACE-OFF23 只覆盖中性闭壳层的 H C N O F P S Cl Br I 分子，算不了离子，所以不参与 IP/EA，只复核 UMA 优化出的中性结构：重原子 RMSD 和弛豫能（MACE 从 UMA 结构出发优化降低的能量）。不用“UMA 结构上的 MACE 残余力”：实测 MMFF 结构与 MACE 的 RMSD 只有 0.02–0.08 Å，残余力却有 1.8–3.6 eV/Å，反映的是硬键长的细微差别。阈值默认 0.3 Å / 0.2 eV（MMFF 结构的弛豫能已有 0.08–0.15 eV），是经验值，等有真实 UMA 结果再校准；超过时可靠性层加 0.3 分（独立模型不同意本身就算存疑）。
**原因：** 用户有云端 UMA 和 MACE-OFF23 medium；对外开放 GPU 有费用和滥用风险，MACE-OFF23 的学术软件许可（ASL）也不允许放进收费功能。mace-torch 固定 e3nn 0.4.4、fairchem 要 e3nn ≥ 0.5，两个模型必须分开环境跑。

## 2026-11-05 UMA 设备选项：自动、NVIDIA、AMD、Apple、CPU

fairchem 2.25（目前最新）只接受 `cuda` 和 `cpu`（`assert device in ["cpu", "cuda"]`）。AMD 显卡在 ROCm 版 PyTorch 里就是 `cuda`，所以能用；Apple GPU（MPS）fairchem 不支持，选 Apple 时在 M 系列 CPU 上跑，页面写明。默认“自动检测”：有 GPU 用 GPU，否则 CPU。桌面版的参数检查同步放宽到这五个值。
**原因：** 用户要求加上 Apple 和 AMD 的选项；不能假装 Apple GPU 可用。

## 2026-11-05 训练页的模型每周四自动核对；网状图改成持续运行的力导向

## 2026-11-05 网状查询重做：以查询为中心的实体网，节点由数据现算

旧版只有约 250 个节点（来源、前 24 个标签、分类、目录官网），只在博客和论坛里出现的程序（如 Shermo）进不了图，搜索只是给已有节点描金边。新版在浏览器里用 `hub/net-engine.js` 从全部条目、19 章讲解手册和 `search-terms.js` 算出约 430 个实体：目录里的软件与数据库、标题里至少出现两次的拉丁名（排除站长随笔、期刊缩写和普通英文词）、术语表的每一组概念、主题标签、资源分类。关系是同一条目里共同出现，标题和标签算 3、摘要和正文算 1，按余弦归一化；宽泛词打折，同一事物的不同写法（DFT / 密度泛函）不算关系；同一篇文章的博客原文和论坛镜像合并成一条。查询依次试精确名、别名、同义词、前缀补全和拼写近似，都不中才做全文检索。
**原因：** 用户要求“搜 Shermo 就让 Shermo 和它关联的东西出现在中心”，并且数据每周更新，所以关系必须现算，不能手工维护。不用图形库，保持全站无构建、可离线。

## 2026-10-31 托管 AI 按可能的花费多计次数，不做 token 记账

一次问答计 1 次（输入不超过 12,000 字、输出上限不超过 4,096 token）。超出按比例多计，`deepseek-v4-pro` 再乘 3（`HOSTED_MODEL_WEIGHTS`）；一次最多 48,000 字，只接受文字。短调用要同时满足输出不超过 400 token、输入不超过 2,000 字，否则按正式问答计。同一账号最多 5 台设备同时登录。
**原因：** 原来只按次数算，一个账号可以用长内容和贵模型花掉远超订阅费的钱，也能多人共用。流式回答里读 token 用量要改动较多，而且只有事后才知道；按请求大小预先计次简单，还能在发送前拒绝。网站发送长对话时会裁掉旧消息，普通用户每次仍只计 1 次。
