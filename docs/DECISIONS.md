## 2026-11-11 xTB 接成在线模型：调 xtb 程序，不开放 IP/EA，GFN-FF 只算中性；新档 open

站长要把 xTB、RDKit、cclib、py3Dmol 等开源工具的功能真正放进站里。浏览器能做的（RDKit.js、3Dmol.js、cclib 式的输出读取）放在代码台；要算力的 xTB 放在站长电脑的在线模型服务里，作为第五条通道。做法是每次能量和梯度调一次 xtb 程序（`--grad`，读 Turbomole 格式的 gradient 文件），而不是 Python 的 xtb / tblite 绑定：conda 的 xtb 程序在 Windows 上有现成的包，绑定没有；这样 chemjobs.py 里的所有任务（优化、频率、构象、扫描、MD、反应路径……）不用改就能用。每次调用开一个临时文件夹，4 个线程。

IP/EA 不开放：在 ETKDG 结构上实测（xtb 6.7.1，绝热），GFN2 的苯 / 乙醇 / 水是 14.2 / 14.4 / 18.1 eV，GFN1 是 15.0 / 15.9 / 20.5 eV，实验约 9.2 / 10.5 / 12.6 eV，差了 4–8 eV（xTB 的参数化本来就不为电离过程，Grimme 组的 IPEA-xTB 是另一套参数）。离子本身的结构和键解离、质子亲和还是可以算的，所以 GFN2 / GFN1 仍标 charged。GFN-FF 是力场，没有电子结构，只给中性闭壳层。

xTB 是 LGPL-3.0，我们只是调用它的程序、不改不分发，结果不受限制，所以新开一档 `open`：所有人免费、不用勾学术用途、和 UMA 共用每天的额度。

OpenMM（蛋白 MD）和 ASE 的更多流程先不做：小分子 OpenMM 要 GAFF / OpenFF 参数化，站长电脑上没有；蛋白 MD 要新的 PDB 输入校验和更长的任务时间，先问站长要不要。

## 2026-11-11 用照片提问：AI 面板直接发图，研习台先把照片读成文字

站长想在 AI 面板和研习台的“学习目标”里粘贴照片提问（打字照旧，照片是多一种方式）。

- **不换模型、不做 OCR：** DeepSeek 的 Flash 模型（就是托管额度和默认设置用的 `deepseek-flash`）在 Chat Completions 里直接收图片（api-docs.deepseek.com/guides/vision，2026-11-11 核对；按 V4 Flash 价格计，每张图最多约 1000 token）。所以图片照 OpenAI 的格式（`content` 里放 `image_url`，base64 的 data URL）发给原来的模型。V4 Pro 文档里没写能看图，选了它时带图的那一问自动改用 Flash，面板上说明；Muse 用 Spark（Wonder 没写能看图）；“其他兼容接口”直接试，失败时提示可能不能看图。浏览器里 OCR（Tesseract 之类）认不了公式和图，模型直接看效果好得多，费用也小。
- **图片先在浏览器里缩小：** 长边 1280 px 的 JPEG（DeepSeek 自己也会缩到约 1300 px），一张大约 100–400 KB，iPad 拍的 HEIC 也经浏览器解码成 JPEG。一次最多 4 张。
- **AI 面板：** 图片只随它那一问发一次；之后的追问只发文字，并告诉模型“这一问附了 N 张图”，模型自己的回答还在上下文里。这样不重复花额度，对话存进 sessionStorage 的也只是 160 px 的缩略图。
- **研习台：先识读成文字（新提示词 `photo`，数据页里能看能改）：** 研习台每一步都要重发附带文件，会话还存在 localStorage、会云同步（免费账号 1 MB），存照片太重。所以附照片时先调一次能看图的模型，把照片里的字、公式、图逐条写成文字（不解题），学员可以展开核对、修改，之后这段文字就当一个附带文件，照片本身不保存。学习目标空着时，用模型给的一句话预填。
- **托管额度放行图片：** 账号服务 `/ai/chat` 改为接受用户消息里的图片部分：只收 JPEG / PNG / WebP / GIF 的 base64 data URL，一张最多 90 万字符、一次最多 4 张、请求体最多 3 MB（别的接口仍是 200 KB），只给 `HOSTED_VISION_MODELS`（默认 `deepseek-flash`）；每张图按 3000 字计入额度（一问带一张图仍是 1 次）。转发前按白名单重建消息，不透传别的字段。2026-11-05 Meta 页“识图只用访客自己的 Muse key”的决定不变（那个页面还是只用 Muse）。
- **上线顺序：** 先部署账号服务，再推网站。旧账号服务会对带图的请求回“托管额度只支持文字内容”，页面照原样显示，不会出错。

## 2026-11-11 游乐场 3D 立体馆：手写的 canvas 2D 三维，VSEPR 用加权的球面点电荷模型

站长要“几个 3D 可操作玩的”游戏。做了四个（16–19），放在新的展区四“立体馆”，和前面的游戏共用标签、地址和成绩（`molastria-play`，云同步里已经有这个键）。

- **不用 WebGL、Three.js 或 3Dmol.js：** 画的东西只有几个球、几根棍、一张多边形和几条圆，canvas 2D 上做透视投影、按深度排序就够了（`play-3d.js` 的 `stage3d`），没有新依赖，桌面版和离线都能用，深浅色直接用 CSS 变量。代价是球与球相交的地方不精确（画家算法），这四个游戏里看不出来。
- **拖空白处转视角，拖球才是操作：** 单指 / 鼠标拖动转视角（画布 `touch-action:none`，手机上画布那一块不能用来滚动页面，画布高度不超过屏宽，剩下的地方照常滚动）；没有做双指缩放。键盘：方向键转，16 里空格选电子对、WASD 推它。
- **VSEPR 的模型：** 电子对是单位球面上的点，推斥 w/r，权重成键–成键 1、成键–孤对 1.2、孤对–孤对 1.5。权重是为了重现 VSEPR 的经验排序挑的（试过 1/r² 到 1/r⁶ 和更大的权重，1.5–2.2 那一档会让 XeF₄ 的孤对挤到 96° 的顺式，不对），页面上写明不是算出来的。测试用多起点放松核对 13 个分子的全局最低都是课本形状。松手时只放松被拖的那一个电子对（坐标下降，玩家自己当优化器）；ClF₃、XeF₂、XeF₄ 有错误的低谷，“自动放松”经常停在那里，页面如实说“停在了局部最低点”，这正是这个游戏要玩的地方。
- **手性用真实分子：** 溴氯氟甲烷、丙氨酸、乳酸、2-丁醇、甘油醛、布洛芬，每轮随机给 R 或 S，说明里写明对应的 D/L 和天然的是哪一种；判断规则是三重积的符号，用 L-丙氨酸的费歇尔投影核对。
- **密勒指数的负号写成 −1，不用组合上划线：** U+0305 在系统中文字体里画歪了（截图里横线落在数字右边），页面上说明课本写法是数字上加一横。(hkl) 和 (−h −k −l) 都算对；(200)、(220) 这类不约分。
- **Bloch 球的关卡目标由一串门算出来，最少门数用广度优先搜索核对：** 数据里不手抄坐标；每个门的转动和它的 2×2 矩阵在测试里逐个对拍。

## 2026-11-10 网状查询没找到的词也匿名汇总到账号服务（站长选的，改了同一天上一条的做法）

上线“只存本机”的版本后，站长在决定卡片上选了“另外匿名汇总到账号服务”，想在账号页看全站哪些词最常搜不到。

- **每个浏览器每个词只报一次，只发这个词和全文命中数：** 在本机第一次记下时发 `POST /net/miss`，不带登录令牌、不带别的搜索；次数因此大致等于“多少个浏览器查过”，同一个人反复搜不会刷高。
- **服务端不存任何关于发送者的东西：** 表 `net_misses` 只有词（NFKC + 小写做主键，另存最近一次的原样写法）、次数、最近一次的命中数、第一次和最近一次的时间。频率限制用一个全站共用的每小时上限（`NET_MISS_HOURLY`，默认 300），不按 IP 计数，所以 `throttle` 表里也没有 IP。代价是有人刷接口时这一小时其他人的词收不到，对一个统计功能可以接受。
- **默认开、可以关：** 网状查询页的“匿名报给站长”默认勾着，页面上写明发什么；取消就只记在本机，关掉“记下术语表认不出的词”则什么都不记也不发。隐私页加了一节。没有做成默认关，因为默认关几乎没人会打开，汇总就没有意义；发出去的只是一个查不到的词，不带身份。
- **两边用同一套过滤规则：** 网址、邮箱、DOI 一类的路径、六位以上的数字（电话、证件号、CAS 号）、太短或太长的输入，浏览器不发、服务端也不收（`missWorth` 照抄 `worthKeeping`，`tools/net-test.mjs` 核对两边一致），手写的请求也存不进地址或邮箱。
- **表最多 3000 行：** 满了先删报得最少、最久没报的，D1 不会被灌满。
- **账号页只给站长看：** “全站没找到的词”一栏（`GET /admin/net-misses`），可以复制、删一个、全部删掉；补进术语表后删掉。没有给词加“查一下”的链接，因为从链接打开网状查询会把站长自己的浏览器也算进去。

## 2026-11-10 代码台扩充：SMILES 用 OpenChemLib 生成坐标，三个新程序的读法用真实输出核对

站长指着愿景页的一条“规划中”（输出解读加 CP2K、NWChem、Q-Chem；从 SMILES 直接生成三维坐标；模型接口算完的结构一键送进输入生成）问能不能做，三件都做了，那一条改成“已上线”。

- **SMILES → 三维坐标用 OpenChemLib（BSD-3，jsDelivr 按需载入，约 2.5 MB），不用页面上已有的 RDKit.js：** RDKit 的 MinimalLib（WASM 版，站上用的 2025.03.4 实测）只有二维坐标（`set_new_coords` 出来 z 全是 0），没有 ETKDG 嵌入和力场；OpenChemLib 有扭转角库的构象生成器和 MMFF94s+。计算放进 Web Worker（Blob 模块，照 `pyrun.js` 的做法），“停止”直接结束 Worker；浏览器不支持就退回页面里算。
- **立体构型：** OpenChemLib 拿三维 molfile 再搭构象时会把手性弄反，所以每个构象都去掉氢、用 idcode 和 SMILES 比一遍，不一样的扔掉；SMILES 没写的构型按第一个搭出的结构定成一种，后面的构象都用这一种，并在页面上写明定成了哪一个（不然不同构象会是不同的立体异构体）。
- **力场不认识的分子（O₂、HCl、硼、金属……）：** 只给一个没优化的结构，明说只是粗糙的起点。自由基按高自旋填多重度，并提醒 MMFF94 是给闭壳层分子做的。
- **三个新读法：** NWChem 7.2.2 用 apt 装、CP2K 2026.2 用 conda-forge 装，在云端会话里真跑本页生成的输入（含故意让 SCF / 优化不收敛、输入写错的几份），摘录放进 `tools/code-fixtures/`；Q-Chem 是商业软件，用 cclib 回归数据里的真实输出（BSD-3，来源写在那里的 README）。只读最常用的几项：最终能量（取最高的相关方法）、收敛、能隙、频率、报错原文。CP2K 默认不打印 HOMO–LUMO 能隙，所以这一项不读，不去猜。
- **真跑时发现生成器的一个错：** CP2K 2026.2 的 `GFN_TYPE` 只接受 0、1、TBLITE，原来写的 `GFN_TYPE 2` 会直接报错；改成 tblite 后端，并说明 conda-forge 的 CP2K 没编进 tblite，跑不了就选 GFN1-xTB。
- **模型接口送到代码台用 localStorage 的 `molastria-code-import`（照 `molastria-lab-import` 的做法），代码台读一次就删：** 多帧的结果（构象、自旋态、反应里的各个分子）每一帧带自己的电荷和多重度，换帧时跟着换；起始帧选能量最低的（构象第 1 名、能量低的自旋态、扫描的最低点、动力学的最后一帧）。
- **示例输出也是真的：** “试一段示例”的 NWChem、CP2K、Q-Chem 三段都从样本文件逐行摘出，测试检查每一行都能在样本里找到。

第 2 步的取舍（同一天，站长说“第二步继续，完成后一起上线”）：

- **key 只存哈希。** `api_keys` 表存 key 的 SHA-256 和开头 10 个字符（`mola_` 加 5 位，给账号页认 key 用），原文只在生成时返回一次。key 是 `mola_` 加 32 个随机字节，每个账号最多 3 个，撤销就是删行，立刻生效。
- **`/v1` 不查来源网站，只认 key。** 跨域头是 `*`：权限来自请求头里的 key，不来自 cookie，所以别的网站替访客发请求也拿不到什么。`/v1` 只收 `mola_` 开头的 key，不收浏览器的登录令牌；反过来 key 也登不进账号（`/me`、`/ai/chat`、`/keys` 都不认它），所以泄露一个 key 最多花掉当天的计算次数，碰不到订阅、邮箱和托管 AI。`/v1/me` 不返回邮箱。
- **次数就是账号在网站上的那一份**（计数器 `uma:<邮箱>`，免费账号每天 100，Pro 支持者 200），不另设。匿名的 40 次只在网站上有：没有 key 就没有账号，接口不给匿名用，否则每换一个 IP 就多 40 次。同一个账号在网站和接口上合起来同时只能有一个任务。
- **MACE 全系不进接口**（MACE-OFF23、MACE-OMOL-0、MACE-MDP，账号服务里 tier 是 `asl` 的全部）。网站上靠访客每次勾选“只用于学术、非商业研究”，程序没法做这个确认，请求里带 `academic: true` 也不行，返回 403 `licence`。
- **和 `/uma` 是同一段代码。** `/v1/jobs` 走的就是 `uma()`，只是身份换成 key 的主人，所以校验、计次、退次和网站完全一致，不会出现两套规则。多出来的只有：回答里带 `cost` 和 `usage`，响应头带 `X-RateLimit-*`。
- **报错给程序看：** `/v1` 的错误是 `{ error: { code, message, message_zh } }`，英文一句、中文一句，`code` 是程序能判断的词（`quota_exceeded`、`job_in_progress`、`offline`、`licence` 等）。网站自己的接口不变，仍是中文一句，由页面翻译。
- **算力如实写。** 账号页、`/api/` 页、`GET /v1`、`llms.txt` 都写明“算力是站长电脑上的 RTX 2080，尽力而为，可能离线”，说明页上还有一个实时的在线状态（读公开的 `/uma/health`）。不承诺可用性，也就不收钱；要承诺是第 3 步的事。
- **所有 key 合起来每天有一个总量**（`API_DAILY_TOTAL`，默认 2000 次，0 表示不设）。任何邮箱都能注册免费账号，多注册几个就能绕过每个账号的 100 次；总量保证脚本再多也挤不掉网站访客在同一块 GPU 上的队列。到了上限返回 429 `api_busy`，不扣次数。

- **没有做：** 任务不按 key 归属（知道 16 位随机任务编号的人都能查结果，和网站一样）。按 key 的用量页和计算接口的 OpenAPI 描述当时没有做，同一天的“五项补充”里补上了（见下）。

五项补充的取舍（同一天，站长在五项里选了“全做”，并要求做完一起上线、发新的桌面版）：

- **用量记录不存分子。** 新表 `api_jobs` 每次用 key 提交记一行：哪个 key（哈希的前 16 位）、模型、计算种类、花了几次、是不是读缓存、时间。SMILES 和坐标不进数据库：账号页不需要它，存了就多一份要保护的研究内容。记录留 30 天，账号页显示最近 10 条；key 撤销后记录还在，显示“已撤销的 key”。只记经 `/v1` 提交的，网站上点的计算不记（次数的计数器是同一个，所以“今天用了多少”是两边合计）。
- **在线率是一行 JSON。** 定时任务（原有的每 15 分钟那个，没有加新的 cron）探测一次 `/health`，结果累加进 `status` 表的 `uptime` 一行：每天一对数字（在线几次、探测几次），留 35 天。`GET /v1/status` 只读这一行，带 5 分钟缓存，不要 key。这样公开接口每次请求只读一行，被人反复刷也碰不到 D1 免费额度；代价是只有“每天百分之几”，没有逐次记录。最近一次探测超过 45 分钟时 `online` 是 `null`（不知道），不冒充“离线”。
- **在线率如实公开，包括难看的时候。** 站长电脑关机的日子就是 0%。这和“尽力而为，可能离线”是一回事：让想用的人自己判断，比写一句“高可用”诚实，也省得别人来问。
- **自动启动用“启动”文件夹里的快捷方式，不用计划任务或 Windows 服务。** 计划任务的“登录时运行”要管理员权限才能建，而 `start.ps1` 有意拒绝管理员身份；服务跑在没有桌面的会话里，隧道的登录信息和 GPU 驱动都在站长自己的账号下。快捷方式不要任何权限，删掉就撤销。代价：电脑开机后要登录才启动；睡眠时离线。`-KeepAlive` 只管“服务自己停了”：两分钟内连续停五次就不再重试（缺包、驱动坏了重试没有用），间隔 5 秒到 2 分钟递增。
- **Python 客户端是一个文件，不是 PyPI 包。** `molastria.py` 没有依赖，`curl -O` 下来就能 `import`，和 `molastria.mjs` 是同一个思路。发 PyPI 要站长的账号和以后每次发版，现在没有用户值得这样做。它自己设 User-Agent（`molastria-python/版本`），因为 Cloudflare 拦 urllib 默认的那个；key 从环境变量 `MOLASTRIA_KEY` 读，不写进代码。已经公开的名字（`Compute`、`submit`、`wait`、`run`、`me`、`models`、`status`、`load`、`MolAstriaError.code`）以后只加不改。
- **chemdb-agent 的计算工具不重试。** 其他适配器遇到 429 和 5xx 会退避重试；计算接口的 429（次数用完、已有任务）和 503（电脑离线）重试没有意义，所以直接把服务的中文说明和 `code` 交给调用它的模型，每个结果都带“RTX 2080，尽力而为，可能离线”这句话，免得模型把离线当成自己的错反复调用。`run_calculation` 默认最多等 120 秒，到时间返回任务编号，不占着 MCP 连接。
- **模型和计算种类的名单有五处**（账号服务、说明页、`openapi.json`、`molastria_compute.py`、`server.py` 的参数），`tools/account-test.ts` 逐一对照，漏改一处测试就失败。
- **没有做批量提交。** 一个账号同时只能有一个任务，批量接口只是替用户排队，还会让一个脚本占住整块 GPU。等第 3 步有了按量付费的算力再做。

## 2026-11-08 桌面版去掉 panic = "abort"

Mac 版 0.1.19 在后台运行约 25 分钟后闪退（SIGABRT，tokio-rt-worker 线程）。按崩溃报告里的偏移反汇编发布包，调用链是：异步回应应用内置协议请求时调用 WKURLSchemeTask 的 `didFinish`，WebKit 已经停掉了这个请求（页面换了、iframe 或视频取消了请求），于是抛出 Objective-C 异常。wry 用 `objc2::exception::catch` 包住了这个调用，本来只会丢掉这次回应；但 `Cargo.toml` 的发布配置写了 `panic = "abort"`，objc2 的文档写明这种设置下接不住异常，Rust 只能报“panic in a function that cannot unwind”并结束整个进程。
**原因：** 应用体积只多一点（unwind 表），换来 wry 的防护真正生效；顺带，命令或后台任务里偶然的 Rust panic 也只结束那一个任务，不再带走整个应用。Windows 不会遇到这个 Objective-C 异常，但两边共用这份配置。以后不要再加回 `panic = "abort"`。

## 2026-10-31 托管 AI 按可能的花费多计次数，不做 token 记账

## 2026-11-10 云同步：原文照存、三方合并、默认关闭

## 2026-11-11 增长看板、访问统计、英文地址
