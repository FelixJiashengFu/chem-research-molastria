## 2026-11-06 首页动态徽标和下载页片头视频只做装饰，素材放在 `public/assets/brand/`

首页 intro 上方放一个循环播放的徽标视频（`logo-loop.mp4`，256×256，约 38 KB），页面 `load` 之后才设置 src，不和首屏抢资源；下载页标题旁放片头视频（`intro.mp4`，960×540，约 1.4 MB，无音轨），只播一次，停在最后一帧。两个视频都静音、无控件、`aria-hidden`、不能用 Tab 选中；`prefers-reduced-motion: reduce` 时不设置 src，只显示 poster（`logo-loop.webp`、`intro-end.webp`）；下载页视频出错、`play()` 被拒或 3 秒没画面时也放回 poster。单文件版（`tools/bundle-single.ts`）只内联 poster 图片，不带视频。顶栏 LOGO、favicon、og.png 和桌面版图标都不动。原始素材（6.8 MB 的 MP4 和 1.1 MB 的 GIF）不进仓库，仓库里只放 ffmpeg 转码后的小文件。
**原因：** 用户要求把动态徽标和片头视频用起来，但它们只是装饰，不能拖慢首屏、不能干扰读屏和键盘操作，也不能在动效敏感的访客那里动。最坏情况（视频播不了）只剩一张静态图，不会是空框。全站统一的品牌标识（顶栏、favicon、分享图）保持原样，免得一处改动牵连所有页面和已安装的应用。

27 条（#188–214），每条的年份、机构、规模、权重和许可证都对照论文（arXiv、Crossref）、Hugging Face 接口与模型卡、GitHub 仓库核实过；查不到的项不写。讲解手册加一章（id `p11c-cat17`），放在“09 · 机器学习：材料与工具”之后，手册变成 20 章。
**原因：** DARWIN 1.5 的 arXiv 页（2412.11970）上作者自己写明这一版“posted prematurely and contains inaccuracies that could mislead readers”，正在大改。链接能打开、也确实是这个模型，但出处本身被作者声明不可靠，所以不收录，章内用一个提示框说明原因；等作者发新版再考虑。打不开的 OpenReview PDF 改用同一论文的 arXiv 版或会议页，不绕过验证。

## 2026-11-06 chemdb-agent 源码进仓库，下载包由确定性打包脚本生成

源码放在 `agent/chemdb-agent/`（和 `deploy/`、`desktop/` 同级），`public/atlas/downloads/chemdb-agent.zip` 只由 `python tools/pack-chemdb-agent.py` 生成：文件清单就是 git 会收的文件，排序、时间戳固定 1980-01-01、权限 0644，同样的源码打出同样的 zip；打包前检查文件名黑名单（.env、.venv、__pycache__ 等）、本机路径、token 形态和录制响应里的 Cookie，命中就中止。离线测试用的录制响应（cassettes）一起提交，录制时自动去掉 key 和 Cookie。
**原因：** 以前 zip 是手放进来的二进制，看不出改了什么，原包里还有本机路径和 Cookie。源码进仓库后改动可审查；打包确定，才能核对“下载包 = 仓库里的源码”。局限：deflate 字节依赖 Python 自带的 zlib，换 zlib 版本可能内容相同而字节不同。

## 2026-11-06 期刊发表栏目：只写官网核实过的内容，不写分区

`journals/` 收 46 种期刊和 2 个预印本平台。每个字段只写期刊或出版社官网（或 Crossref 登记的元数据）能核实的内容，附出处链接和核对日期；核实不了的项不写，详情里列出“以下几项没有在官网核实”。影响因子、APC、审稿时间只写官网明确写出的数字。中科院分区和 JCR 分区不写具体值，只在“怎么选刊”一章解释是什么、去哪里查。指导正文是自己写的经验总结，具体规定都链回官方页面。
**原因：** 期刊规定和费用每年变，转述二手信息很容易错；分区来自第三方、要订阅才能核对、每年调整，写进来就是没法核实的数字。对官网返回人机验证的出版社（Elsevier 作者指南、`pubs.acs.org` 等）不绕过，宁可少写几项。

## 2026-11-06 论文与社区的国际来源：只用官方接口、Discourse 公开 JSON 和 RSS

新增 14 个国际来源（Stack Exchange 两个站、matsci.org 等 5 个 Discourse 论坛、6 类博客与机构新闻、GitHub 发布说明），Crossref 期刊 4 → 22 种，arXiv 50 → 100 条，官方软件与数据库目录 29 → 80 条；国际来源条目过半。只用官方 API、Discourse 的公开 JSON 和 RSS/Atom，逐个查 robots.txt；遇到人机验证、证书错误、没有订阅源的站点就不收（Reddit r/comp_chem、Rowan 博客、CECAM 等），不抓 HTML。每个来源有条数上限；某个来源这周失败或返回空时沿用上周它的条目。英文条目按关键词归进站内已有主题；网状查询里英文条目的标签只按整个标签匹配实体（不认标签名里的子串）。`check-catalogue.mjs` 加了“来源消失”和文件体积上限（`hub/data.js` 1.6 MB、`merged-data.js` 3.2 MB）。

## 2026-11-06 桌面版下载一律走系统保存窗口：页面只交字节和建议名，上限 256 MB

桌面版以前没有下载处理：Windows（WebView2）静默存进“下载”文件夹，Mac（WKWebView）直接取消。现在注入脚本拦下所有 `<a download>`（站内文件、blob:、data:，包括 iframe 里的），把字节和建议文件名交给应用命令 `save_download`，由 tauri-plugin-dialog 弹出系统保存窗口，用户确定后原样写入，取消就什么都不写。命令没有路径参数，文件名在 Rust 端清理（去路径、非法字符、方向控制字符、Windows 保留名，截到 200 字节）；同一时间只开一个窗口；超过 256 MB 拒绝并提示。`capabilities/default.json` 不变：不给页面任何 `dialog:*`、`fs:*` 权限。
**原因：** 和 2026-11-05“页面只传参数”同一思路：页面会显示外部内容，不能让它决定写到哪里；路径只来自用户在系统窗口里的选择。不用 Mac 的 `WKDownload`，因为它要 macOS 11.3+，而最低版本是 11.0。256 MB 是因为文件在页面和应用里各占一份内存。

## 2026-11-06 讲解手册单独成栏目 `manual/`，顶栏放不下的入口收进“更多”

手册阅读器从数据库页（`atlas/`）拆到 `manual/index.html`，地址是 `manual/index.html#<章节 id>`；旧地址 `atlas/index.html#guide[/<id>]` 用 `location.replace` 跳过来（网页、file:// 和单文件版都测过）。正文数据仍在 `atlas/content.js` 和 `atlas/guides-en.js`，因为网状查询、build-seo、net-test、i18n-extract 都从那里读；静态版 `guide/` 照旧由 CI 生成。顶栏“讲解手册与数据库”拆成“讲解手册”和“数据库”，“Agent 工程”仍是 `atlas/index.html#agent`。桌面宽度下顶栏只占一行：放不下的入口从末尾依次收进“更多”菜单（按实际宽度算，不写死数量）；手机宽度仍是整行横向滚动。

## 2026-11-05 在线模型扩到 15 个：只有 ANI-2x 进 Pro，其余免费；每个模型一次一人

站长要求把电脑上部署的模型都开放，“只把 ANI-2x 放入 Pro，其他模型都免费开放给所有人，但是要排队，一次只能一个人使用一个模型”。做法：每个模型一个队列、一次算一个任务；每位访客同时只能有一个任务（账号服务传哈希后的访客 ID）；fairchem、ANI-2x、MACE 三条通道并行。
**原因：** MACE 的学术软件许可（ASL）第 13 条只许学术、非商业用途，明确排除“增强商业产品或服务”；MolAstria 有付费 Pro，所以 MACE 不进 Pro、对所有人次数相同，并要访客勾选学术用途。站长说是学术用途，这样做也把 MACE 和收费功能分开；要彻底稳妥，可以向 MACE 作者要书面许可。ANI-2x 是 MIT，可以收费。eSEN、AllScAIP 和 UMA 同为 FAIR Chemistry License。
**哪些模型开放 IP/EA：** 按垂直 IP 实测（苯 / 乙醇 / 水）。UMA-S 1.2、AllScAIP 两个都接近实验值，开放；UMA-S 1.2.1 和 D4rev 水偏低（约 6 eV），开放但页面提示和 1.2 对照；UMA-S 1.1、eSEN 三个、MACE-OMOL-0 电荷态能量差不可靠（乙醇约 5 eV、水接近 0），只算中性分子，免得“阳离子”悄悄得到中性的结果。MACE 在 GPU 上用 float64（小分子只要一两秒）。UMA-M 1.1 的权重 11 GB，这台电脑装不下，不上线。

## 2026-11-05 在线 UMA：站长电脑的 GPU 经账号服务和 Cloudflare Tunnel 对所有访客开放

站长要求“对所有人开放”。访客不直接连电脑：请求先到账号服务 `/uma/*`，由它检查来源网站、按访客每天限次（匿名 20、Pro 100）、挡住受全面制裁的地区、只转发校验过的字段并加上共享暗号；电脑上的服务只听 127.0.0.1、只认暗号、一次算一个、按规范 SMILES 缓存。只开放 UMA-S 1.2.1 的 ipea 和 opt（显存 8 GB，不同时加载 UMA-M）。Windows 上没有 Triton，用 fairchem 的 `batch` 预设（全精度、不编译）；FEC 的 IP/EA 实测 8.8 秒。电脑关机时页面显示离线；服务没开通前面板整个隐藏。
**原因：** FAIR Chemistry License v1 授权使用、复制、分发和衍生，没有禁止提供计算服务，但要求遵守可接受使用政策和出口管制，并由使用者对第三方索赔负责，所以页面写明禁止用途和不作保证，服务端加地区限制。直接把家里电脑暴露在公网太危险，隧道加暗号加账号服务三层把电脑和访客隔开；推荐再加 Cloudflare Access 服务令牌，让不合规的请求在 Cloudflare 就被拦下。

## 2026-11-05 云端 GPU 只做站长的批量计算；MACE-OFF23 作为独立模型复核 UMA 的中性结构

站长的 L4 虚拟机不开公网服务，由 `tools/cloud/run.mjs` 经 gcloud 开机、计算、取回、关机，结果用 AI 实验室原有的 CSV 导入。MACE-OFF23 只覆盖中性闭壳层的 H C N O F P S Cl Br I 分子，算不了离子，所以不参与 IP/EA，只复核 UMA 优化出的中性结构：重原子 RMSD 和弛豫能（MACE 从 UMA 结构出发优化降低的能量）。不用“UMA 结构上的 MACE 残余力”：实测 MMFF 结构与 MACE 的 RMSD 只有 0.02–0.08 Å，残余力却有 1.8–3.6 eV/Å，反映的是硬键长的细微差别。阈值默认 0.3 Å / 0.2 eV（MMFF 结构的弛豫能已有 0.08–0.15 eV），是经验值，等有真实 UMA 结果再校准；超过时可靠性层加 0.3 分（独立模型不同意本身就算存疑）。
**原因：** 用户有云端 UMA 和 MACE-OFF23 medium；对外开放 GPU 有费用和滥用风险，MACE-OFF23 的学术软件许可（ASL）也不允许放进收费功能。mace-torch 固定 e3nn 0.4.4、fairchem 要 e3nn ≥ 0.5，两个模型必须分开环境跑。

## 2026-11-05 UMA 设备选项：自动、NVIDIA、AMD、Apple、CPU

fairchem 2.25（目前最新）只接受 `cuda` 和 `cpu`（`assert device in ["cpu", "cuda"]`）。AMD 显卡在 ROCm 版 PyTorch 里就是 `cuda`，所以能用；Apple GPU（MPS）fairchem 不支持，选 Apple 时在 M 系列 CPU 上跑，页面写明。默认“自动检测”：有 GPU 用 GPU，否则 CPU。桌面版的参数检查同步放宽到这五个值。
**原因：** 用户要求加上 Apple 和 AMD 的选项；不能假装 Apple GPU 可用。

**原因：** 用户要求模型模块每周更新、网状查询要有 Obsidian 那样的灵动感。

## 2026-11-05 网状查询重做：以查询为中心的实体网，节点由数据现算

旧版只有约 250 个节点（来源、前 24 个标签、分类、目录官网），只在博客和论坛里出现的程序（如 Shermo）进不了图，搜索只是给已有节点描金边。新版在浏览器里用 `hub/net-engine.js` 从全部条目、19 章讲解手册和 `search-terms.js` 算出约 430 个实体：目录里的软件与数据库、标题里至少出现两次的拉丁名（排除站长随笔、期刊缩写和普通英文词）、术语表的每一组概念、主题标签、资源分类。关系是同一条目里共同出现，标题和标签算 3、摘要和正文算 1，按余弦归一化；宽泛词打折，同一事物的不同写法（DFT / 密度泛函）不算关系；同一篇文章的博客原文和论坛镜像合并成一条。查询依次试精确名、别名、同义词、前缀补全和拼写近似，都不中才做全文检索。
**原因：** 用户要求“搜 Shermo 就让 Shermo 和它关联的东西出现在中心”，并且数据每周更新，所以关系必须现算，不能手工维护。不用图形库，保持全站无构建、可离线。

## 2026-11-05 桌面版跑 UMA：脚本编译进应用，页面只传参数

桌面版的“在本机运行”用访客自己的 Python（自动找 `py -0p`、PATH、python.org 和 conda 的安装位置，也可以填路径）。要跑的 Python 脚本 `uma/runner.py` 用 `include_str!` 编进应用，页面只能传 SMILES、任务、模型、设备、电荷、自旋，Rust 端逐项校验；解释器必须是叫 python / python3 的绝对路径。日志用轮询取（和更新进度一样），没有引入前端 Tauri 包。计算结果写在应用数据的 `uma-runs/` 下，IP/EA 通过 localStorage 交给 AI 实验室导入。

## 2026-10-31 托管 AI 按可能的花费多计次数，不做 token 记账

一次问答计 1 次（输入不超过 12,000 字、输出上限不超过 4,096 token）。超出按比例多计，`deepseek-v4-pro` 再乘 3（`HOSTED_MODEL_WEIGHTS`）；一次最多 48,000 字，只接受文字。短调用要同时满足输出不超过 400 token、输入不超过 2,000 字，否则按正式问答计。同一账号最多 5 台设备同时登录。
**原因：** 原来只按次数算，一个账号可以用长内容和贵模型花掉远超订阅费的钱，也能多人共用。流式回答里读 token 用量要改动较多，而且只有事后才知道；按请求大小预先计次简单，还能在发送前拒绝。网站发送长对话时会裁掉旧消息，普通用户每次仍只计 1 次。
